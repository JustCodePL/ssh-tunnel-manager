v1.0.25 STABLE 28 May 2026

Host header overrides for Portless forwards

Portless forwards can rewrite the upstream Host header, and disconnecting no longer hangs on portless tunnels.

Host header override

Services behind a host-routing reverse proxy (Portainer, Traefik, nginx) now work when reached through *.ssh-local. In this release the toggle is on by default. When the field is empty and RemoteHost looks like an FQDN, that name is used automatically. The setting is stored in ~/.ssh/config.

Disconnecting and the settings window

Shutting down a portless tunnel now has a time limit, so the save spinner in the tunnel form can't lock up. Dragging a text selection out of an input no longer closes the forward settings window.

How to use it

  • Click the ⚙ on a port forward and fill in Host header override.
  • Turn off the toggle to opt out.

Known limits

  • The override works for HTTP only.
