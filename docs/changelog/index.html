v1.2.0-beta.5 BETA 8 November 2026

Security fixes: host keys, saved passwords and links

Three fixes from a security review of the code. Every SSH connection now verifies the server, a saved password no longer goes to a jump host, and deleting a link no longer touches what it points to.

Every connection verifies the server

Until now only tunnels with a saved password checked the server's host key, and ~/.ssh/known_hosts was not read. Now every connection is checked: tunnels, the terminal, Files, jump hosts and ProxyCommand. A server in known_hosts, or one whose key you accepted, connects as before. An unknown server opens the main window with its fingerprint and connects only after you trust it. A changed key stops the connection and it is not retried.

A saved password stays away from the jump host

A tunnel's saved password was also offered to its ProxyJump host. The jump host now gets only keys and the agent, and the password goes only to the server behind it.

Deleting a link deletes only the link

In the Files window, deleting a symbolic link to a folder used to remove the contents of that folder. Now only the link goes, and the confirmation says so. Links whose target no longer exists can be deleted too.

How to use it

  • When the Unknown server dialog appears, compare the fingerprint with the one from the server's administrator, then choose Trust this server or Cancel.
  • To see or remove accepted keys, open the tunnel's settings, go to its credentials and use Forget host keys.
  • If a key changed for a good reason, forget the old key there, or update known_hosts if that is where it is listed.

Known limits

  • A server missing from known_hosts asks once per tunnel and address, also during auto-connect. With no answer within 90 seconds the tunnel stops with an error, and you connect it again by hand.
  • A jump host that accepts only passwords no longer works with a saved login. It needs a key or the agent.
  • A saved password still reaches a server behind an SSH forward when you open Terminal, Files or the Editor on that forward.
  • The screenshot comes from the test build in a browser. The dialog was tested there and not by hand in the desktop window.
  • The limits of the previous beta still apply.
