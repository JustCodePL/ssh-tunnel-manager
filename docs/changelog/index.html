What changed in SSH Tunnel Manager

What each release changes and how to use it. Installers and files are on the release page.

v1.2.0-beta.2 BETA 3 November 2026

Failed tunnels stop retrying and report errors in the app

A tunnel that can't connect no longer retries forever or sends a system notification on every attempt.

Three attempts, then stop

The tunnel shows reconnecting between attempts and tries up to 3 times in a row.

A red exclamation mark and the error in the app

After the third failed attempt the card shows a red ! and the error. A toast appears for a few seconds. The tray menu marks the tunnel with ! too. Tunnel errors no longer appear as system notifications.

How to use it

  • Fix what the error describes, then click connect. You get another 3 attempts.
  • Click logs to see each attempt and its error.

Known limits

  • After 3 failed attempts nothing retries on its own. A tunnel that connects at login before the network is up has to be connected by hand.

v1.2.0-beta.1 BETA 3 November 2026

Built-in remote desktop and actions on port forwards

Open RDP inside the app, with no external client, through the host's SSH connection.

Remote desktop

A host where an RDP server answers on port 3389 gets an rdp button after connecting. Logins are saved in the OS keychain only after they have worked. The server certificate is remembered on first use, and a change has to be accepted before connecting.

Actions on port forwards

Each forward has a type: rdp, ssh or undefined. Typed forwards get buttons on the tunnel card: rdp, term and files. They open on the forward's target, so a machine behind a bastion is reachable directly.

How to use it

  • Connect a host and click rdp on its card.
  • For another RDP port, set rdp port in the host's advanced options. Other ports are never scanned.
  • On macOS, Cmd acts as Ctrl on the remote desktop, and only the right Option key acts as AltGr.

Known limits

  • No remote audio.
  • Tested against GNOME Remote Desktop on Ubuntu. Windows RDP servers, Windows and Linux clients, the clipboard and a physical keyboard on macOS have not been tested yet.

v1.1.0 STABLE 29 October 2026

Persistent Portless on macOS and a notarized app inside the DMG

On macOS 13+ Portless keeps working after a reboot, once you approve a signed system service.

Portless system service on macOS

The service restores DNS, loopback aliases and forwarding on privileged ports at boot, for every macOS account. If its registration goes stale, the app shows a recovery hint. Local ports remain as a fallback.

Logs, updates and the DMG

Application logs go to a private file with bounded rotation, also for background launches. The app relaunches reliably after an update when it was started at login. The macOS app inside each DMG carries its own stapled notarization ticket. In the port forwarding form, the add action sits below the list.

How to use it

  • On macOS 13+, approve the signed Portless system service once.
  • Inspect, refresh or remove the service in Settings.

v1.0.30 STABLE 19 June 2026

Richer Docker and htop monitoring

The Docker view gets groups, container details and sorting, and the htop view can sort processes.

Docker

Containers are split into active and stopped groups, with stopped collapsed by default. Click a container to see live CPU and RAM usage, published port mappings, mounts, networks and environment variables. A sort bar orders the list by name, CPU or RAM. Auto-refresh is gone: the list refreshes when you open the window, click ⟳ or change the sort. The plain listing runs only docker ps, so it loads much faster on small VPSes.

htop

A sort bar orders processes by CPU, memory, name or PID.

Reliability

Docker and htop are detected again on every connect, so a tool installed since your last connection shows up without restarting the app. Remote commands are no longer cut off after a hardcoded 8 seconds. Docker commands get 45 seconds, and timeout errors report how long they actually waited.

v1.0.29 STABLE 14 June 2026

Live remote host monitoring

A connected tunnel shows live data from the remote host. Stats go over the existing SSH connection, with no extra connections or agents on the remote.

CPU and RAM

A compact usage bar appears under the host on every connected tunnel.

Disk

The disk button opens a window listing all mounts with usage bars.

Docker and htop

On hosts where docker is detected, the docker button opens a live container view. On hosts where htop is detected, the htop button opens a graphical monitor with per-core CPU bars, RAM and swap, load average, uptime and the top processes. term still gives you a full shell. Detected tools are remembered per host, so the buttons stay visible across app restarts, disabled until you reconnect. Clicking one re-checks the tool and tells you if it's no longer installed.

How to use it

  • Turn the CPU and RAM widget on or off in Settings, in the monitoring section.
  • Click disk, docker or htop on a connected tunnel.

v1.0.28 STABLE 3 June 2026

Safer Portless defaults and reliable Linux updates

The Host header rewrite on portless forwards is now opt-in, and after an update on Linux the new version runs.

Host header rewrite is opt-in

For portless forwards the rewrite is off by default and applies only when you enable it per forward, in the forward settings (⚙). The previous automatic rewrite on FQDNs broke plain TCP and other non-HTTP services. Configs that set an explicit value keep working.

Updates on Linux

After installing an update the app relaunches into the new binary, as on macOS and Windows. Before this, the old version kept running after Install & Restart.

v1.0.27 STABLE 29 May 2026

Privileged Portless ports on Linux

On Linux, portless forwards on privileged ports such as :80 now work. macOS and Windows are unaffected.

A clear error and a one-click fix

These forwards used to fail silently because the process lacked CAP_NET_BIND_SERVICE. The only trace was a buried log line. The app now detects this and shows an in-app banner and a desktop notification with the exact setcap command for your binary. The auto-updater re-applies the capability after replacing the binary. Packagers get a PolicyKit policy file, and the README has a section on portless mode on Linux.

How to use it

  • Click [ AUTHORIZE ], which uses PolicyKit and pkexec setcap.
  • Click [ RESTART NOW ] to apply it.

v1.0.26 STABLE 29 May 2026

Built-in SFTP file editing

Text, config and source files open from the SFTP browser straight into a built-in editor.

The editor

It is based on CodeMirror, with syntax highlighting for common web and DevOps formats. Files load and save over SFTP with no local temp copies. Unknown formats can be forced open as plain text. You can edit next to the file list or pop the editor out into its own window, with minimize, as with the terminal.

Saving

If the file changed on the server since you opened it, the app warns before overwriting. Writes are atomic and keep the file's permissions. Switching to another file with unsaved changes asks whether to save, discard or cancel.

Auto-connect on startup

Tunnels flagged to connect on startup now connect when the app launches.

v1.0.25 STABLE 28 May 2026

Host header overrides for Portless forwards

Portless forwards can rewrite the upstream Host header, and disconnecting no longer hangs on portless tunnels.

Host header override

Services behind a host-routing reverse proxy (Portainer, Traefik, nginx) now work when reached through *.ssh-local. In this release the toggle is on by default. When the field is empty and RemoteHost looks like an FQDN, that name is used automatically. The setting is stored in ~/.ssh/config.

Disconnecting and the settings window

Shutting down a portless tunnel now has a time limit, so the save spinner in the tunnel form can't lock up. Dragging a text selection out of an input no longer closes the forward settings window.

How to use it

  • Click the ⚙ on a port forward and fill in Host header override.
  • Turn off the toggle to opt out.

Known limits

  • The override works for HTTP only.

v1.0.23 STABLE 28 May 2026

Portless .ssh-local domains

A forward can get its own name under .ssh-local instead of a port on 127.0.0.1.

Portless mode

With the portless toggle on, a forward gets a dedicated 127.0.1.x loopback IP and is published as <domain>.ssh-local through a DNS server built into the app. If the address is in use, the next IP is tried. An optional exposed port sets what the clipboard and tray give you: an http:// or https:// URL when bound to 80 or 443, otherwise host:port.

One-time admin setup

Each platform needs it once: an NRPT rule on Windows, /etc/resolver on macOS, a systemd-resolved drop-in on Linux. The app asks for it on the first portless connect.

Form and tunnel cards

Each forward has its own block in the edit form, with the description on top. Clicking a forward tag on a tunnel card copies the address and shows a toast. Editing a connected tunnel reconnects it live.

v1.0.0 STABLE 2 March 2026

First public release

The first public release of SSH Tunnel Manager, a desktop app for managing SSH tunnels on Windows, macOS and Linux.

Tunnels and config

SSH runs in pure Go (golang.org/x/crypto/ssh), so no system ssh binary is required. The app reads and writes Host blocks in ~/.ssh/config and keeps its own metadata in comments that survive each save. Local port forwarding is included.

System tray

The tray is the primary interface, with a status badge and colored indicator dots.

Installing and updating

The app updates itself from GitHub Releases. Windows has an NSIS installer.
