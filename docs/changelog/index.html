What changed in SSH Tunnel Manager

What each release changes and how to use it. Installers and files are on the release page.

v1.2.0-beta.2 BETA 3 November 2026

Failed tunnels stop retrying and report errors in the app

A tunnel that can't connect no longer retries forever or sends a system notification on every attempt.

Three attempts, then stop

The tunnel shows reconnecting between attempts and tries up to 3 times in a row.

A red exclamation mark and the error in the app

After the third failed attempt the card shows a red ! and the error. A toast appears for a few seconds. The tray menu marks the tunnel with ! too. Tunnel errors no longer appear as system notifications.

How to use it

  • Fix what the error describes, then click connect. You get another 3 attempts.
  • Click logs to see each attempt and its error.

Known limits

  • After 3 failed attempts nothing retries on its own. A tunnel that connects at login before the network is up has to be connected by hand.

v1.2.0-beta.1 BETA 3 November 2026

Built-in remote desktop and actions on port forwards

Open RDP inside the app, with no external client, through the host's SSH connection.

Remote desktop

A host where an RDP server answers on port 3389 gets an rdp button after connecting. Logins are saved in the OS keychain only after they have worked. The server certificate is remembered on first use, and a change has to be accepted before connecting.

Actions on port forwards

Each forward has a type: rdp, ssh or undefined. Typed forwards get buttons on the tunnel card: rdp, term and files. They open on the forward's target, so a machine behind a bastion is reachable directly.

How to use it

  • Connect a host and click rdp on its card.
  • For another RDP port, set rdp port in the host's advanced options. Other ports are never scanned.
  • On macOS, Cmd acts as Ctrl on the remote desktop, and only the right Option key acts as AltGr.

Known limits

  • No remote audio.
  • Tested against GNOME Remote Desktop on Ubuntu. Windows RDP servers, Windows and Linux clients, the clipboard and a physical keyboard on macOS have not been tested yet.
