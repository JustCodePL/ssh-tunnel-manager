v1.2.0-beta.7 BETA 25 November 2026

Fixes for logins that hang: the SSH agent and ProxyCommand

Connecting no longer wears out the SSH agent, and a connection through a ProxyCommand can no longer hang forever or leave its helper running. Nothing changes in the interface.

The SSH agent keeps answering

Every connect and reconnect opened a connection to the SSH agent and never closed it. After enough of them the agent, on macOS the system one, stopped answering: logins in the app hung, and so did ssh in the terminal. The app now closes each agent connection when its request ends, and gives up on an agent that does not answer: for each request, 5 seconds to connect and 5 to list keys, 60 seconds for a signature, because an agent may ask you to confirm it. A silent agent is skipped, and the login goes on with the default key files and a saved password, if the tunnel has one. When the agent is running but holds no keys, the default key files in ~/.ssh (id_ed25519, id_ecdsa, id_rsa) are now offered instead.

ProxyCommand connections end cleanly

A login through a ProxyCommand that failed, for example on a refused host key, could hang while closing. The SSH handshake through a ProxyCommand now has a limit of 2 minutes, enough for a command that opens its own connection or waits for a sign-in in the browser; past it the error says there was no answer. Time spent on a host key question does not count. Disconnecting stops the command together with the processes it started, such as aws ssm start-session, ssh -W or cloudflared, not just the shell around it. The command's error output is kept only up to its last 16 KiB.

Terminal and Files on a forward stay open

Terminal and Files opened on the server behind an SSH forward closed on their own about 10 seconds after the connection renewed its keys, which happens after a lot of data, for example a large transfer, or after a set time on some servers. They now stay open.

How to use it

  • Nothing to do. If logins hung with an earlier version after many reconnects, they work again after updating.

Known limits

  • For Terminal and Files on the server behind an SSH forward, the whole login has 10 seconds, so a signature you confirm in the agent (ssh-add -c, a password manager) must be confirmed within that time.
  • A helper that detaches itself from the ProxyCommand (for example with setsid, or by turning into a daemon) keeps running after disconnecting.
  • On Windows, a process that the ProxyCommand starts before the app adds the command to its group keeps running; if the group cannot be set up, only the command itself is stopped.
  • These fixes were tested with automated tests, not by hand against real ProxyCommand helpers.
  • The limits of the previous beta still apply.
